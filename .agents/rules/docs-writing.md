# 文件撰寫規則

適用於本專案（暖心待辦看板 kanban-app）所有說明文字：`README.md`、使用說明、變更紀錄、commit 訊息、程式碼註解，以及畫面上給使用者看的文字。

## 語言與用語

- 一律使用台灣繁體中文與台灣慣用語，不使用中國大陸用語。程式碼、指令、檔案路徑、識別字維持原文。
- 常見對照：

  | 不用 | 改用 | 不用 | 改用 |
  |---|---|---|---|
  | 軟件 | 軟體 | 用戶 | 使用者 |
  | 代碼 | 程式碼 | 默認 | 預設 |
  | 項目（project） | 專案 | 設置 | 設定 |
  | 信息 | 資訊 | 文檔 | 文件 |
  | 網絡 | 網路 | 支持（功能） | 支援 |
  | 運行 | 執行 | 調試 | 除錯 |
  | 函數 | 函式 | 變量 | 變數 |
  | 服務器 | 伺服器 | 登錄 | 登入 |

- 「文件」指 document；指 file 時用「檔案」。
- 標點使用全形中文標點（，。：；「」），中英文之間不強制加空格，但同一份文件要一致。

## 術語

- 英文術語第一次出現時，若讀者可能不熟，用「中文（English）」格式，例如「拖放（drag and drop）」；之後可以只用中文。
- 已有通用中譯就用中譯，沒有的沿用原文；不自創縮寫或非通用簡稱。
- 同一個概念全專案用同一個詞。本專案固定用語：
  - 看板（board）、欄位（column）、任務卡片（task card）
  - 狀態欄位：畫面目前顯示英文 **To-do**、**Process**、**Done**，文件提到時照畫面原文寫，必要時補中文說明，例如「**Process**（進行中）」。
  - 優先程度：畫面顯示 **High**、**Medium**、**Low**，寫法同上。
  - 畫面文字若改成中文，本節與既有文件要一併更新。

## 寫法

- 先寫結論或操作結果，再補原因。一段只講一件事。
- 操作步驟用編號清單，每步一個動作，按鈕與選單名稱照畫面原文寫，並用粗體標示，例如「點 **新增**」。
- 指令放進程式碼區塊，標明在哪個目錄執行。
- 不寫「非常」「強大」「輕鬆」這類形容詞堆疊，也不寫行銷語氣；描述功能實際能做什麼。
- 提到網址、版本號、外部服務（GitHub Pages、Vercel 等）的操作方式時，註明可能因對方改版而不同，並附官方文件連結。

## README 結構

`README.md` 依序包含下列段落，沒有內容的段落可省略：

1. 專案名稱與一句話說明
2. 線上展示連結
3. 功能
4. 本機使用方式（直接開啟 `index.html` 即可，無需建置）
5. 檔案結構（`index.html`、`style.css`、`app.js` 各負責什麼）
6. 部署方式
7. 已知限制（例如資料存在瀏覽器本機，換裝置或清除瀏覽器資料就會消失）

## Commit 訊息

- 第一行用中文寫「做了什麼」，不超過 50 個字，結尾不加句號，例如：`新增卡片拖放排序`。
- 需要補充時空一行再寫原因或影響範圍。

## 隱私

- 文件、截圖與範例資料不放真實姓名、email、公司名稱或內部資訊；範例待辦用中性內容（例如「整理會議紀錄」）。
